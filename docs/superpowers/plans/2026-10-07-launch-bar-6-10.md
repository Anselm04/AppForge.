# Launch Bar 6-10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining machine-enforceable AppForge launch-bar gaps for security boundaries, production recovery, monitoring/evidence, repeated real-customer proof, and false-green prevention.

**Architecture:** Preserve the existing auth, billing, build, certification, Fly, Redis, Supabase, monitoring, and recovery implementations. Add one fail-closed production database backup/restore proof and one top-level launch-bar evidence gate that consumes existing workflows rather than duplicating provider logic. Physical provider acceptance remains owner-controlled and must never be simulated.

**Tech Stack:** TypeScript/Vitest, GitHub Actions, PostgreSQL/pg_dump, Fly.io, Supabase, Redis/BullMQ, existing AppForge observability/certification code.

**Spec:** `docs/superpowers/specs/2026-10-07-launch-bar.md`

## Global Constraints

- Do not change AppForge pricing, product identity, or payment separation.
- Do not hard-code credentials, phone numbers, provider tokens, or other products into AppForge.
- Do not use Sprites for repository/CI work.
- Do not add Fly machines.
- Real provider acceptance remains the owner's physical test; automation must fail closed rather than fake provider success.
- Reuse existing launch-bar 1-5 implementations; do not duplicate them.

## Review Focus

- Missing production DB backup credentials must produce an explicit non-green result, never a silent pass.
- Backup artifacts must be encrypted before persistence and a restore rehearsal must prove the dump is usable.
- Launch certification must bind evidence to the exact current `main` SHA rather than accepting stale successful runs.
- Repeated customer-journey evidence must require multiple successes, not a single run.
- Manual auth/admin/customer evidence must remain real and must not be replaced with manufactured tokens or bypasses.
